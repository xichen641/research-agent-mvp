# ReID 科研任务人工评审标准 v1

对应：`evaluation/datasets/reid_research_tasks.jsonl`；固定材料为 `corpora/reid-v1.json`。
任务版本与评分标准版本均为 1。本文件定义人工判断依据，不包含实测回答或评测分数。
本轮按本地固定 PDF 审校后的逐题改动及原页依据见
[任务集原文审校记录](reid_task_source_audit.md)。首次发布前仍保持版本 1；任务指纹
已经变化，此前生成的评分模板应保留并重新生成，不能套用旧记录。

## 任务与来源

题库共 20 个任务，五类各 4 个。题目、设想和用户对话均由评测设计者编写，
`scenario_origin=synthetic_fixture` 表示合成题目/对话，而论文证据来自真实的固定 PDF。
R04 中 E1 的数值属于合成用户自报场景，不是本地实验、论文或真实模型验收结果。

| 任务 | 核对重点 |
| --- | --- |
| M01 | CLIP-ReID 两阶段的冻结/学习参数与推理图像表示 |
| M02 | MP-ReID 的人工属性条件、隐式提示原文定义和显式对齐 Q/K/V |
| M03 | IDEA 的前缀、文本反演、共享采样位置和全局/局部 Q/K/V |
| M04 | NEXT 的文本调制阈值采样、共享 soft routing 和聚合 Q/K/V |
| C01 | CLIP-ReID 与 PromptSG 的训练、pseudo token 含义和两种推理选择 |
| C02 | 反演全局/局部贡献、交互 Q/K/V 和推理成本边界 |
| C03 | 人工属性、VQA 和离线 captions 的输入条件与噪声入口 |
| C04 | 共享位置偏移、阈值采样与专家 soft routing 的区别 |
| H01 | 描述细节、错误属性、截断；前缀 token 数不等于 caption 字数 |
| H02 | MLLM 自报置信度、校准与跨模态冲突 |
| H03 | 六篇的对象/输入/数据集/协议；VehicleID 表头与正文指标标签冲突 |
| H04 | 作者消融、参数/FLOPs 变化、用户决定和待验证假设分开 |
| E01 | 明确视觉基线、身份采样及扰动位置，区分语义/容量/训练策略 |
| E02 | NEXT Table 4 的类型/Quality/模型列；人工质量和下游收益分别评估 |
| E03 | 无文本模型、图像-文本模态组合、检索时空文本与缺图像分别定义 |
| E04 | 原 batch 身份配对与 12GB 假设；推理小验证、训练与停止条件 |
| R01 | 至少两次真实压缩后，最新更正有效且旧设置可追溯 |
| R02 | 同空间接续 PromptSG 推理接口/材料确认及未执行的 20 图检查，另一空间隔离 |
| R03 | 假设采纳、撤回、删除后的有效状态与历史解释 |
| R04 | 用户结果更正/撤销、作者结果和未提供的新材料版本 |

实际 ID 带 `REID-` 前缀。每题的 `paper_scope` 是提问范围；`sources` 提供
论文 ID、SHA-256、材料版本、从 1 开始的 PDF 物理页码、章节/图表定位和原文片段。
`fact_checks` 关联这些来源并给出语义回答要点，允许合理的同义表达，不能只命中
一个关键词就视为满足全部要点。开放题另有 `required_analysis`、`error_boundaries`、
`next_step_requirements` 和五项 `scoring_focus`。

`fact_checks` 中的可接受回答按本题实际问题与必要分析使用；部分论文事实是供
反证或实验设计查阅的背景，不要求回答把所有背景逐字复述。R02/R03 主要检查
用户状态，提供的论文来源也不能取代用户消息。准确的简短回答不因未罗列无关
数值而扣分，直接询问的参数、操作或数值则必须说明其条件和归属。

原文校验只规范化 Unicode 字形、引号、空白、PDF 断行及英文词内连字符；不做
同义词替换或模型推断。片段匹配不能自动证明其支持某个解释或数字：评审者仍须
回读完整相关页，检查表头、图注、单位、数据集和条件。尤其 H01 中 IDEA Figure 4
的 prompt length 指前缀可学习 token，不能解释成自然语言 caption 字数。

本轮特别核对以下容易混淆的边界：

- H03：CLIP-ReID 也评测车辆；第 6 页 Table 3 的 VehicleID 列为 R1/R5，邻近
  正文将 85.3/97.6 写作 mAP/R1。应报告表列并指出冲突，不补造 VehicleID mAP。
- H01：IDEA Figure 4 曲线与邻近“增长”文字概括并不完全一致，应保留原文差异；
  NEXT Table 4 的 Quality 是作者噪声消融设定，不等于人工属性正确率或校准率。
- E03：IDEA 附录第 16 页 Table 12 的 R/N/T 包含图像及其文本；Table 13 的
  M(X) 是检索时把对应文本置为空字符串。其 Full 80.2 与 M(RNT) 79.5 的 mAP
  差异为 0.7 个百分点，不能转述成删除三路图像仍保有该结果。主文 Table 6 的
  `IDEA w/o Text` 属于另一模型消融，也不能与 Table 13 合并为同一个实验。
- M02：保留 MP-ReID 的 `training dataset-specific common text descriptions`
  定义；未核对实现索引时不强行推导“每 ID 独立”或“全数据集严格共享一组参数”。
- E04：用户的 12GB/一天是合成验收条件；原文 batch=64 的 16×4 身份采样、
  24GB 硬件及实际损失条件要分别记录，梯度累积不能直接保证配对条件等效。

## 执行与记录

1. 先运行题库原文校验。以相同语料版本、问题、模型与配置执行任务，保存原始回答、
   来源引用、模型运行 ID/导出文件，以及必要的任务/压缩/状态事件。T0.3 交付题库，
   实测回答、延迟、Token 和成本属于 T0.4。
   只将问题与实际材料提供给被测智能体；`sources.excerpt`、`fact_checks`、
   `required_analysis`、`scoring_focus` 和本评审标准由评审者使用，不能作为 gold
   答案注入模型输入。资料关联应指向已核对的 PDF 哈希与版本，不凭显示名认定。
2. 单轮题使用 `prompt`；连续题按 `turns` 顺序发送 `user_message`，根据
   `space_key` / `session_key` 创建或切换验收用空间和会话。在每轮之后核对 `checks`。
   这些 key 是验收逻辑标签，不是已有数据库 ID。
3. 缺少空间、跨会话记忆、撤回、版本固定等能力时，记为 `capability_missing` 并说明
   操作与证据；实际执行失败记 `execution_failed`。不要由模型口述“已保存/已压缩”
   推断后端操作成功，也不要用模拟成功替代缺失能力。
4. 人工逐项核对回答及其来源。论文事实要读固定原文；用户约束、决定、实验报告和
   更正要读原消息。模型回答、摘要、记忆或研究者自己的推断不成为论文证据。
5. 填写五项分数、具体理由、来源/原消息引用与阻断问题。来源引用使用该题的
   `source_id`；原消息检查点使用 `turn:T01` 等。实际回答位置记录到 `answer_refs`，
   不使用 gold 回答作为模型已经回答的内容。

R01 的补充追问按以下固定循环执行，保持 T02 的更正不变：

1. 要求列出语义分支收益的三个竞争解释。
2. 要求设计一个固定 backbone 的最小对照。
3. 要求核对该对照的潜在混淆因素。
4. 要求整理尚未执行的下一步及停止条件。

每次完整循环后核对真实压缩事件或摘要覆盖范围；最多执行 10 个循环。观察到两次
压缩后发送 T03。若不能确认压缩次数，记录验证未完成/能力缺失，不能以 40 轮
对话代替“两次压缩”的证据。R01 到 R04 属于未来持续研究能力的固定回归场景，
当前版本不支持时如实记录。

## 五项 0/1/2 分锚点

每一项必须有理由。下面以题库中的具体任务给出评分示例，结合每题的
`scoring_focus` 使用，不是要求答案逐字复述 gold。

| 维度 | 0 分示例 | 1 分示例 | 2 分示例 |
| --- | --- | --- | --- |
| `factual_grounding` 事实依据 | M01 把第一阶段说成图文编码器同时学习，或引用不存在的页；R04 把作者结果当作用户实验 | M01 正确识别学习 token，但没有完整说明第二阶段或缺少可回读来源 | M01 完整区分两阶段、冻结参数及推理表示，并能回读对应原页；R04 正确区分作者数据和用户陈述 |
| `task_understanding` 任务理解 | E01 只给一般训练流程，没有回答如何区分收益来源 | 给出基线/语义对照，但没有匹配参数、训练预算或训练策略 | 对照分别检验语义、容量、策略，固定关键条件，回应用户“还没有训练”的状态 |
| `analysis_boundaries` 分析边界 | H02 把 0.95 自报置信度说成已校准的 95% 正确率，或 H04 将试验决定写成证实 | 知道有不确定性，但没有解释冲突/误差或形成可检验解释 | 明确自报分数与经验校准不同，分析跨模态冲突与错误传播；事实、推断、假设和决定保持区别 |
| `actionability` 下一步可执行性 | E04 保证 12GB 能直接运行原 batch，或者写出未实测的显存/耗时 | 建议 AMP/降低 batch，但缺少材料确认、显存探测和停止条件 | 提供材料/代码确认、小样本和显存检查、单模块对照、降级和停止判据，符合一天与 12GB 条件 |
| `context_continuity` 上下文连续性 | R01 两次压缩后又使用 CLIP-ReID/24GB；R02 混入另一空间；R03 重用失效假设 | 使用 PromptSG/12GB，但不能解释更正来源、原因或旧设置的去向 | 采用 T02 最新设置，回读更正理由与 T01 历史；跨会话停点、空间隔离和撤回状态都可核对 |

单轮题也要评 `context_continuity`：检查是否遵守当前题目的论文范围、训练/推理
条件及资源设定，不补造用户历史。没有历史消息并不自动得 2 分，也不自动判 0 分。

识别原文冲突、准确说明未明确的代码/协议条件属于分析能力，不能要求智能体
为了与一句 gold 相同而掩盖冲突。需要核对的数字应保留数据集、表格行列、指标、
单位和训练/测试操作；百分数差值使用“百分点”，不与相对提升百分比混用。

## 通过与阻断规则

每项至少 1 分且总分至少 8/10；任何阻断问题均不通过。

- `[2,2,1,2,1]` 总分 8、无阻断：通过。
- `[0,2,2,2,2]` 总分 8：不通过，事实依据为 0。
- `[1,1,1,1,1]` 总分 5：不通过。
- 五项全为 2，但存在伪造引用：仍不通过。

以下属于阻断问题：捏造论文事实、数值或不存在的来源；混淆对象、数据集或评价
协议后作性能结论；将未执行的实验写成结果；把用户自报数值归给论文；把采纳的
假设、撤回/删除的判断写成有效已证实事实；混入另一空间的研究状态；历史引用
改指未经提供或核对的新版本。

准确说明局部缺证据并继续有边界的分析，不因无法填造结果而扣成 0 分。
开放题不要求预定的唯一研究方向；只要满足本题分析、边界与下一步要求，可以
接受替代假设、对照或可解释的缩小范围。

## 评审文件与汇总

在后端开发环境中生成空白模板：

```powershell
python -m research_agent.evaluation.research_tasks review-template --output ../.tmp/reid-research-review.jsonl
```

初始 `execution_status=not_run`，五项 `score=null`，不会生成实测结果或默认高分。
模板绑定每题的 `task_sha256` 和 `rubric_version=1`；修改任务后，旧评分不能悄然
复用。为保护已填写记录，生成模板不覆盖已有文件。

完成实际回答的人工核对后，填写 `execution_status=completed`、真实 `run_id`、
`reviewer`、带时区的 `reviewed_at`、`answer_refs` 和五项 `ratings`。每项包含
`score`（整数 0/1/2）、`reason` 和 `evidence_refs`；`blocking_issues` 记录具体错误。
缺失能力或执行失败只填对应状态及 `failure_reason`，不伪造五项答案分数。

```powershell
python -m research_agent.evaluation.research_tasks review --reviews ../.tmp/reid-research-review.jsonl
```

汇总工具验证题目 ID、任务版本、来源引用、分数范围和通过阈值；不会调用模型替
人评分。仍有 `not_run` 返回 `pending`（退出码 3），存在失败返回 1，全部通过
返回 0，文件/结构错误返回 2。单个题目的高分不能抵消另一个题目的阻断问题。
人工评分、回答、轨迹、实验日志等运行数据保存到 `.tmp/`，不作为源码提交。
